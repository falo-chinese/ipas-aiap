# 前端圖片渲染修正（`practice/v3.01_image_demo.html`）

> 資料已正確，**目前跑掉的是前端**。本文件列出三個 bug 與可直接套用的修改。  
> 搭配 `verification/09_修正版題庫_含正確圖片對應.csv` 與 `verification/figures/`（檔名已改為 `fig_` 前綴）。

---

## 三個 bug

### Bug 1：路徑被強制改寫成 `images/`

`processData()` 目前的寫法：

```js
if (imgName.includes('/')) {
    const fname = imgName.split('/').pop();
    imgUrl = `images/${fname}`;      // ← 丟掉原本的資料夾
} else {
    imgUrl = `images/${imgName}`;
}
```

CSV 給的是 `figures/fig_B2-003.png`，被改寫成 `images/fig_B2-003.png`。
新圖放在 `practice/figures/`，**前端永遠找不到**。

### Bug 2：`;` 多檔字串被 `split('/')` 截斷

`圖片檔名` 欄可能含多個檔案，以 `;` 分隔（題組共用圖在前、該題自有圖在後）：

```
figures/fig_G_B2-043_p13.png;figures/fig_G_B2-043_p14.png
```

`split('/').pop()` 會取到 `fig_G_B2-043_p14.png` —— **只剩最後一張，前面的全部遺失**。
目前有 **21 題**是多檔，全部受影響。

### Bug 3（已由我端修正，但需了解）：檔名衝突

`practice/images/` 內有我更早提供的**整題版面渲染圖**，命名為 `<編號>_p<頁>.png`。
新版裁切圖原本也用同樣規則，於是 27 個檔名相撞——前端改寫路徑後，
抓到的是**舊的、內容不同的圖**。這是「修了還是跑掉」的直接原因。

已將所有新圖改為 `fig_` 前綴（`fig_B2-003.png`、`fig_G_B2-043_p13.png`），
與 `practice/images/` 的既有檔案**零衝突**。

## 修改內容

### 1. `processData()` —— 取代圖片路徑那段

```js
// 舊：把任何路徑改寫成 images/<basename>，且只取單一檔
// 新：路徑照用，支援 ';' 多檔
let raw = (row['圖片檔名'] || vals[10] || '').trim();
if (raw.toLowerCase() === 'none' || raw.toLowerCase() === 'null') raw = '';
const images = raw ? raw.split(';').map(s => s.trim()).filter(Boolean) : [];

return {
    id: id,
    qno: qno,
    filename: filename,
    question: questionText,
    options: opts,
    answer: ansIdx,
    answerIndex: ansIdx,
    images: images,                        // ← 陣列
    group: (row['題組'] || '').trim(),      // ← 新欄位，例如「第43~47題」
    needsManualCheck: (row['圖片待人工確認'] || '').trim() === '是'
};
```

### 2. `render()` —— 圖片區塊改為渲染全部

```js
${q.images.length ? `
    <div class="q-image-container">
        <div class="q-image-label">
            📷 題目附圖${q.group ? `（${q.group} 共用情境）` : ''}（點擊可全螢幕放大）
        </div>
        ${q.images.map(src => `
            <img src="${src}" class="q-image-preview" alt="試題圖片"
                 loading="lazy" onclick="app.openLightbox('${src}')">
        `).join('')}
    </div>
` : ''}
```

移除原本的 `onerror` fallback（指向 `assets/q_images/`）—— 那會在找不到新圖時
悄悄載入舊的錯誤圖，讓問題更難察覺。寧可讓它顯示破圖。

### 3. `render()` —— 篩選條件

```js
if (this.filterMode === 'img_only') {
    filtered = this.questions.filter(q => q.images.length > 0);
}
```

### 4. 寫死的題數

HTML 內有兩處寫死「52 題」：

```html
<p>…支援 52 題考題圖片…</p>
<button …>📷 僅顯示圖片題 (共 52 題)</button>
```

實際為 **47 題**。建議改為啟動後動態填入：

```js
document.getElementById('btn-filter-img').textContent =
    `📷 僅顯示圖片題 (共 ${this.questions.filter(q => q.images.length).length} 題)`;
```

## 驗收方式

套用後，用以下檢查確認每一筆都能解析：

```js
// 貼進瀏覽器 console
app.questions.filter(q => q.images.length).forEach(q =>
  q.images.forEach(src => {
    const i = new Image();
    i.onerror = () => console.error('載入失敗', q.id, src);
    i.src = src;
  }));
```

無錯誤輸出即表示 47 題、50 個圖檔全部正確解析。

重點抽查三題（這三題最能暴露前述 bug）：

| 題號 | 應顯示 | 驗證什麼 |
| --- | --- | --- |
| `B2-043` | 2 張：vgsales 程式碼＋資料表 | 多檔渲染、題組共用圖 |
| `B2-044` | 與 B2-043 **完全相同**的 2 張 | 題組成員共用同一組圖 |
| `B3-038` | 1 張：`sum((y_true-y_pred)**2)/len(y_true)` | 相鄰題不再共用同一張 |

`B3-039` 應顯示 Dropout 的 `np.random.binomial(...)`，與 `B3-038` **不同圖**。
若這兩題看到同一張，表示仍在讀舊資料。
